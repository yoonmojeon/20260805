## 3. UI에서 볼 것

| UI 항목 | 설명 |
|---------|------|
| 데이터 경로 | `자동 라우팅` / `운항 DB 강제` / `문서 RAG 강제` |
| 애매한 질문은 LLM으로 재분류 | 저신뢰일 때 Ollama로 한 번 더 |
| 다시 보기 | `운항만으로 다시` / `문서만으로 다시` / `둘 다로 다시` |
| 예시 버튼 | 운항·문서·hybrid 샘플 |
| 답변 상단 배너 | `[경로: ops / rag / chat / hybrid | …]` |
| Evidence / crop | rag 표 질문이면 Evidence Table + 표 crop |
| 보고서 다운로드 | Noon/MRV `.docx` |

확인 포인트는 배너에 `ops` / `rag` / `hybrid`가 맞게 찍히는지다.

흐름 예:

- `현재 CII 알려줘` → ops → SQLite
- `MSC 111 주요 결과 알려줘` → rag → Text Chroma
- `선령별 탱크 검사 범위 알려줘` → rag → Table Chroma → crop
- `우리 CII와 관련 규정 같이 알려줘` → hybrid

## 4. 검증 시나리오

**자동 라우팅**으로 순서대로 넣어 본다.

### A. 운항 DB로 가야 하는 질문 (ops)

| # | 질문 | 기대 경로 | 성공 기준 |
|---|------|-----------|-----------|
| A1 | 현재 운항 상태 알려줘 | ops | 배너에 `운항 DB (ops)`, 위치·SOG·연료·배출 등 수치 |
| A2 | 올해 CII 등급을 알려줘 | ops | Attained/Required/A~E 등급 언급 |
| A3 | 이전 항차 분석해줘 | ops | 직전 항차 KPI 요약 |
| A4 | Noon Report 생성해줘 | ops | 답변 + 하단 파일 다운로드에 `.docx` |
| A5 | 연간 MRV 보고서를 생성해줘 | ops | MRV Annual `.docx` 생성 |

실패 예:

- 배너가 `문서 RAG`로 뜸 → 라우팅 실패
- `운항 SQLite DB가 아직 없습니다` → `python ops/scripts/load_hodata.py` 필요

### B. 문서 RAG로 가야 하는 질문 (rag)

| # | 질문 | 기대 경로 | 성공 기준 |
|---|------|-----------|-----------|
| B1 | 최신 MEPC 회의 주요 내용을 정리해줘 | rag | 배너에 `문서 RAG (rag)`, MEPC 관련 내용 |
| B2 | MSC 111의 주요 결과를 요약해줘 | rag | MSC 111 관련 요약 |
| B3 | DNV에서 자율운항 관련 Rule/Guidance를 찾아줘 | rag | DNV 문서/가이드 인용 성격의 답 |
| B4 | KR 규칙에서 검사 관련 요건을 알려줘 | rag | 선급 규칙 쪽 답변 |

실패 예:

- `문서 RAG 인덱스가 아직 없습니다` → 인덱스 미구축
- 배너가 `운항 DB`로 뜸 → 라우팅 실패 (이 경우 `문서 RAG 강제`로 재시도해 비교)

### C. 강제 경로 테스트

같은 질문을 경로만 바꿔 확인합니다.

1. 질문: `올해 CII 등급을 알려줘`
2. `운항 DB 강제` → ops 배너 + CII 수치
3. 질문: `최신 MEPC 회의 주요 내용을 정리해줘`
4. `문서 RAG 강제` → rag 배너 + 회의 내용

강제 모드에서만 되고 자동에서 안 되면 **라우터** 문제,  
강제에서도 안 되면 **해당 DB/인덱스** 문제입니다.

### C2. hybrid / 멀티턴

| # | 질문 | 기대 경로 | 성공 기준 |
|---|------|-----------|-----------|
| H1 | 우리 CII랑 MEPC 규제 같이 알려줘 | hybrid | 배너 `hybrid`, 운항/문서 섹션이 나뉨 |
| H2 | (H1 다음) 그럼 더 자세히 | hybrid | 이전 주제 유지 |
| H3 | (MEPC 질문 다음) 그럼 우리 배는 괜찮아? | hybrid | 문서 맥락 + 우리 선박 비교 |
| H4 | (ops 질문 다음) 문서로 봐줘 | rag | 경로 전환 |

## 5. 데이터가 어떻게 나뉘는지

```text
질문
  ├─ chat → 안내 템플릿 (DB/문서 검색 없음)
  ├─ ops  → SQLite data/maritime.db
  │         (센서·항차·CII·Noon/MRV)
  └─ rag  → Chroma data/processed/index/unified_full_corpus_715_v1/
            (선급 규칙·IMO MEPC/MSC 문서 청크)
```

| 구분 | 엔진 | 경로 |
|------|------|------|
| 안내 | 고정 프롬프트 | `prompts/chat.py` |
| 운항 | SQLite + Python Tool | `data/maritime.db` + `prompts/ops.py` |
| 문서 | Chroma + e5 임베딩 | `data/processed/index/unified_full_corpus_715_v1/` + `prompts/rag.py` |
| PDF 원본 | (검색 DB 아님) | `data/raw_pdfs` → 바탕화면 `자료` |

운항 DB와 문서 인덱스는 섞이지 않습니다. 잡담/소개는 chat으로 빠집니다.

## 7. 자주 나는 문제

| 증상 | 원인 | 조치 |
|------|------|------|
| Ollama 미연결 / LLM 오류 | `ollama serve` 안 뜸 | Ollama 실행 후 재시도 |
| 운항 DB 없음 | Excel 미적재 | `python ops/scripts/load_hodata.py` |
| 문서 인덱스 없음 | Chroma 미구축 | `data/processed/index/unified_full_corpus_715_v1` 확인 |
| 문서 질문이 느림 | 첫 로딩·임베딩 모델 로드 | 첫 질문만 느릴 수 있음 |
| 라우팅이 반대로 감 | 키워드 애매 | `운항/문서 강제` 사용 또는 LLM 재분류 ON |
| GPU를 안 쓰는 것 같음 | torch가 CPU 빌드 | `python -c "import torch; print(torch.cuda.is_available(), torch.__version__)"` → `True` / `+cu128` 여야 함 |
